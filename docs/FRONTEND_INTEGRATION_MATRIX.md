## Konvensi handoff bersama — PROPOSED

- **Respons:** sukses `{ data, meta }`; gagal `{ error: { code, message, details } }`. Adapter memetakan data server ke props presentasi; props React bukan schema API. ID stabil dan field nullable perlu disepakati.
- **Daftar:** perlu pagination/cursor, limit maksimum/default, sorting stabil, filter diterapkan, dan metadata navigasi. `Pagination` saat ini menerima `page/pageCount/onPageChange`, bukan bukti server memakai pagination halaman (`src/components/ui/Pagination.jsx:3–14`). Jangan membuat total/pageCount palsu bila server memilih cursor.
- **Filter:** URL lokal mengenal `q/from/to/project/member/status/priority`; bukan query API yang disepakati. Pencarian dan tanggal menerima input lokal; pilihan proyek/anggota/status/prioritas disabled. Rentang terbalik mempertahankan input/URL dan menampilkan error. Tanggal malformed/mustahil atau parameter tanggal berulang mempertahankan URL, menampilkan input kosong dan error sampai diperbaiki/reset; jangan kirim request invalid (`src/features/common/FeatureUI.jsx`, `dateFilters.js`). Arti tanggal, inklusivitas batas, pencarian, reset pagination, dan sorting perlu konfirmasi.
- **State:** bedakan layanan belum terhubung, loading, error, hasil kosong terverifikasi, dan data berhasil dimuat. `null` progres bukan `0`; jangan tampilkan sukses sebelum mutasi dikonfirmasi server.
- **E-baca:** rencana penanganan jaringan/timeout, `401`, `403`, `404`, `429`, dan `5xx`; bentuk final belum disepakati. Keputusan membedakan objek tidak ada/tidak berizin harus berasal dari backend, bukan keberadaan ID pada URL.
- **E-mutasi:** E-baca ditambah `409` konflik/version, `422` validasi per field, double-submit, serta hasil gagal yang tidak menghapus input. Jangan retry mutasi otomatis tanpa kontrak idempotensi. Pilih respons kondisi tersimpan atau kewajiban refetch; invalidasi daftar/ringkasan/progres/aktivitas harus jelas.
- **Capabilities:** kebutuhan konseptual baca/buat/edit/arsip/kelola anggota/checklist/laporan per objek; nama key belum dipilih. Jangan menyimpulkan semua izin dari role atau menyalakan kontrol berdasarkan UI saja. Auth, kebijakan visibilitas, dan capability tetap PROPOSED.
- **Waktu/progres:** PRD menetapkan progres dari checklist dan agregasi berbobot, bobot positif, serta larangan progres manual. UTC server/Asia Jakarta UI, default bobot 1, dan rincian cakupan/pengecualian agregasi masih usulan. UI tidak mengisi bobot default dan tidak menghitung progres domain. Nilai otoritatif, alasan nilai tidak tersedia, dan cakupan harus jelas dalam kontrak sebelum adapter dibuat.

## Penghubung UI internal — bukan kontrak API

Empat halaman daftar menerima resource melalui props: `TasksPage({ tasks, members })`, `TeamProgressPage({ progress })`, `MembersPage({ members })`, dan `ActivityPage({ activity })`. Entry resource memakai `{ status, scope, items, onRetry }` sebagai model UI internal, bukan payload jaringan.

- `status`: `unavailable`, `loading`, `error`, atau `success`; array kosong pada success adalah hasil kosong terverifikasi.
- `scope`: string persis `pathname + search` dari React Router. Resource tanpa scope cocok tidak dirender; perubahan pencarian/filter segera menyembunyikan item dan callback retry lama. Ini pengaman tampilan saja, bukan cancellation request, authorization, atau pengganti isolasi cache/sesi kelak.
- `items`: array props presentasi untuk TaskCard, MemberCard, MemberProgressList, atau ActivityList. Success tanpa array diperlakukan sebagai error, bukan kosong. Mapping schema backend baru dibuat setelah kontrak disetujui.
- `onRetry`: callback opsional pada error; tanpa callback tidak ada tombol retry. Loading/error tidak mempertahankan item sebelumnya dan UI tidak menampilkan detail error server mentah.
- Route aplikasi tidak memasok resource; runtime tetap unavailable, filter tetap URL lokal, dan pagination tidak dipasang tanpa metadata/kontrak. State berisi hanya diuji lewat props sintetis dalam tes dan harness browser di `tests/browser/fixtures/`, bukan fallback aplikasi.
- Form tugas menyatukan field dan rancangan checklist dalam state induk. ChecklistDraft controlled tidak menjadi schema create/update API, tidak menyimpan data, dan tidak membuat progres/status selesai.

## Urutan integrasi dan kriteria serah-terima

1. **Setujui kontrak dan environment terlebih dahulu.** Catat keputusan/version kontrak, URL tanpa secret, schema request/response/error, capability, dan aturan progres. Jangan mengaktifkan login/mutasi berdasarkan proposal saja.
2. **Tambahkan client/adapter frontend setelah persetujuan.** Cancellation pada request usang, state aman saat sesi berubah, mapping error aksesibel, serta pemisahan schema server/props. Jangan menyimpan kredensial atau token rahasia di `localStorage`, dan jangan menaruh secret pada `VITE_*`.
3. **Integrasikan baca sebelum mutasi.** Bootstrap sesi, opsi domain, daftar/detail/filter/pagination. Guard navigasi hanya UX; uji server menolak akses tanpa izin, termasuk request langsung yang melewati UI.
4. **Aktifkan mutasi berdasarkan capability terverifikasi.** Uji validasi, konflik, double-submit, kegagalan jaringan, refetch/hasil tersimpan, dan perubahan agregat/aktivitas. Reload harus menunjukkan hasil persisten, bukan state lokal.
5. **Buktikan penerimaan end-to-end.** Akun uji yang disediakan backend untuk variasi akses, 401/403/404/409/422/429/5xx sesuai kontrak, null vs nol, daftar kosong vs unavailable, filter lintas halaman, timezone, logout/expiry dan perubahan izin. Tes UI lokal yang tercatat di `FRONTEND_STATUS.md:69–94` bukan verifikasi API atau authorization produksi.

Handoff ini tidak mengubah backend, dependensi, database, seed, konfigurasi secret, atau repository bersarang `flexboard/`. Tidak ada klaim deployment, runtime health berhasil, maupun persetujuan kontrak baru.
